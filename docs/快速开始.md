# 仿ZZZ渲染 · MMD 0.2.1｜通用版快速开始

**普通 Blender 插件，安装到 Goo，不是 DSH 插件。**

使用顺序：**MMD Tools 导入绝区零 PMX → 选择对应游戏 JSON / 贴图 → 扫描 → 一键配置并渲染**。插件会在建立渲染场景与着色前执行 MMD Tools 原生分材质并证明数据等价；无需提前手拆，不需要角色名单，也不需要另找默认模板。**分部 Object / Mesh 和局部槽 / 索引可变，不再承诺“不拆网格”。**

> **必须提供对应角色、对应外观的游戏材质 JSON 与贴图。** 无 JSON 路线已停止。资源目录无效会阻断；个别材质槽找不到足够证据时，该槽在列表顶部红色标出并默认保留 MMD 原材质，不会冒充成游戏材质。

## 一、准备什么

- **Goo Engine 4.4**，并自行安装、启用 **MMD Tools**。具体环境版本与验证范围以实际验证记录为准；普通 Blender 不提供等效降级。
- 自己有权使用的绝区零 **PMX**。
- 对应角色 / 外观的**完整游戏资源目录**，通常含 `Materials` 与 `Textures`。也可选择 `Materials` 子目录；**不是 PMX 的 `tex` 文件夹**。避免混入多个角色、多个不明确外观或同名重复资源。
- 一个可写、能长期保留的输出文件夹。

插件包不含角色模型、贴图、游戏 JSON 或 MMD Tools，也不含任何 .blend 模板：渲染场景、着色器、描边与合成器均由插件代码生成。Goo 节点不兼容会报错，请使用 Goo Engine 4.4。

## 二、安装与第一次出图

1. 在 Goo 中打开“编辑 → 偏好设置 → 插件 → 从磁盘安装”，选择完整 ZIP，启用“**仿ZZZ渲染 · MMD**”。无需另选任何模板。
2. 先保留工程副本，用 MMD Tools **自行导入 PMX**。常用基线为默认单位、比例 `0.08`、保留原日文骨名，导入 Mesh / Armature / Morphs / Display；之后要用物理还须导入 Physics。比例、骨数不是角色白名单。
3. 建议在干净导入副本上先配置，再导入 VMD / 编辑 Pose / 构建物理或加入复杂自定义动画。保留 MMD Tools 原生材质节点；退出材质 Morph 临时预览和 UV Morph 编辑预览。旧式 UV Morph `DATA`、Mesh-only drivers、以原网格为目标的外部约束 / 修改器等须先在独立文件处理并验证，详见[完整说明](<../zzz_mmd_toon/README.md>)第 4 节的输入边界。
4. 切到**对象模式**，选 MMD 根物体（或所属骨架 / 网格），按 `N` 打开“**仿ZZZ渲染**”侧栏。
5. 设置“**资源目录**”（对应角色JSON与贴图目录）及输出目录，点“**扫描**”。
6. 材质列表里**红色置顶**的是未映射槽：点选后可在该槽自己的候选 JSON 里改选并点“使用所选JSON”（选择自动记到资源目录 `zzz_mapping.json`，下次沿用），或点“保留MMD原材质”。也可调该槽描边宽度。不处理也行：点一键渲染时第一次只提示，再点一次就忽略未映射槽直接渲染。
7. 点“**一键配置并渲染**”（或高级设置的“**仅配置 / 不渲染**”）；底部状态栏会显示进度。输入预检后，依次保存 `00` 完整回退 → 原生 `separate_by_materials(clean_shape_keys=False)` → exact provenance 核对与材质 Morph 网格引用迁移 → 保存 `01` 分离后、着色前回退 → 建立渲染场景 → 建立材质桥、逐面描边、灯光与双层合成。校验、保存新工程后再渲染；渲染场景创建发生在分离清理完成之后。
8. 按面板输出路径打开本次唯一时间戳目录，查看新工程、PNG 和配置验证报告。已有工程 / 回退点不会被覆盖；原 PMX 与游戏资源文件不会被改写。

输出文件夹留空时，已保存工程使用其目录下的专用输出文件夹；未保存工程使用临时目录。想长期保留结果，请显式选择输出位置。

## 三、怎样理解自动关联

**通用的是算法，不是“任意模型百分百成功”的承诺。** 没有角色名单、专用 profile 或固定骨 / 材质计数门槛。每个原材质都走相同的解析与判断流程：

- 像素相似度先关联 **atlas 贴图族**，再按每个原槽的中 / 日 / 英语义、原生透明度 / 双面与 JSON 状态分别选择参数。共享 atlas 的脸、眼、眉和透明变体不会因 MainTex 相同被合并；HairShadow 也不当头发表面。
- 显式纹理名称优先。无 `Name` 引用只有在结构 / 独立 PMX 图像证据唯一时才推断，并记录 `inferred`。**推断不是 PathID 解码，也不证明恢复了游戏原绑定**；不会跨 JSON 只按指针数字绑定。
- 必需主贴图、数据图或 JSON 身份缺失 / 歧义会阻断。无可靠绑定的可选 MatCap 会记录未解析并关闭相应贡献，不按编号猜槽位；画面可能因此少效果。
- 编辑过的翅膀或重合叠层只有在唯一语义 / 严格几何证据下才可能借用数据参数，并保留原色和 Alpha；诊断会说明推断，不代表支持所有改造。
- **参数关联与关闭叠层分开证明。** 同源叠层仅在 100% exact 有向位置 / 全部 UV / 三角重复计数覆盖、独立语义与所有排名前兼容 JSON 完整路径 / 数据族唯一时借参数，保留原色 / Alpha / 可见性；这不证明动画重复。`MME_DUPLICATE_OFF` 还需完整权重、全部 ShapeKey、作者法线空间、无相关 Morph / 动画风险等证明，以及供体 / 效果层双面一致、可解码 sphere **ADD（`'2'`）**、源主图全部像素 **Alpha max `<= 0.35`**；主图 / sphere 只接受无 Image 动画的静态 `FILE` / `GENERATED`，不以序列 / 影片的当前帧证明全动画。证据不足保留，不再用旧 `> 0.995` / round-6 无向位置集合自动隐藏；参数关联不唯一则阻断。
- 背面剔除：保留原材质已经开启的值与 PMX 单面要求；直接 JSON 表面的明确 `_Cull=2` 不被 `_DoubleSided=1` 抵消（眼 / 口 / 贴花另有双面预览策略），仅借参数的叠层保留自己的原生状态。自动关闭还要证明供体 / 效果层**最终 raster 剔除一致**。这是通用 Goo 预览规则，不声称所有 Unity pass / 游戏剔除等价。
- 目影：无贴图 / 贴图两类改用有色 Transparent BSDF，保留常量 / 独立 atlas Alpha，并乘原生实例 Alpha；不执行黑色 Forward、描边或 AOV。配置后可在目影映射行调“目影透射颜色”，越接近白越淡，A 不控制不透明度；Alpha Morph=0 仍白色透射。默认线性透射 `(.713,.687,.687)` 是预览选择，不是原游戏参数证明。
- 命中分部归入 `ZZZ_MME重复叠层_保留关闭_...`，名称前缀 `MME_OFF_`，仅默认 `hide_render=True`。网格、原 Material 与 Morph 仍在；可在 Outliner 的**该分部**相机开关手动恢复，原值记录在 `zzz_effect_was_hide_render`，证据在报告 / `zzz_effect_parts`。不删除、不硬改发色、不覆盖输入。取消隐藏只恢复**当前游戏 Forward 叠层，不是原 MME 原样效果**；恢复未挂桥的原生材质状态需打开 `00`（原布局）或 `01`（已分离、未着色）完整文件。

| 看到什么 | 应做什么 |
| --- | --- |
| 必须选择资源目录、没有可解析 JSON | 选择完整的对应游戏资源根目录，而非 PMX 纹理目录。 |
| 必需贴图缺失 / 无法解码 | 补齐同一外观的资源，检查文件可读性，再扫描。 |
| JSON / atlas / state 无法唯一关联 | 排除混入资源、同名文件、重复 JSON stem、PMX 改图或语义歧义。插件不会按文件排序猜一个；无法解决时保留诊断供检查。 |
| 可选 MatCap 未解析或特效不同 | 这是资源绑定或能力边界，不可把“能出图”当游戏完整还原。 |

资源齐全与关联成功，只说明可以进入当前重建流程。Eye_E、物理透射、部分发光 / 变身 / 武器效果、Unity blend / depth / stencil 状态仍未实现或近似；**仿 ZZZ 预览不是逐像素复现**。

## 四、原生分材质、原骨、Morph、动作和物理

- **实际分离网格，但保留逐面原 Material 数据块 / Material ID。** Object / Mesh ID、名称、局部顶点 / 槽 / 面索引可变；不按共享 MainTex 合并、不以新渲染材质取代原身份，不重绑或自动权重。未初始化的负值 Material ID 只在 `00` 后由 MMD Tools 自身 API 初始化并记录；重复非负 ID 阻断。
- **先证明再建新基线：** 临时 POINT / EDGE / CORNER / FACE 来源索引逐项核对坐标、全部组与权重（含零权重、未使用组及锁）、UV active / render / clone / 默认颜色层结构、全部形态键、面绕序及原 Material、所有稳定作者属性 typed bytes。原面 / 原角各保留一次，边界顶点 / 边可复制。作者法线核对 signed-short2、sharp / smooth 和边 / 角拓扑的原始存储，不用运行时法线缓存替代；只在原层存在且来源子集全 False 时按原索引恢复分离省略的 sharp / 现有 UV pin BOOLEAN 层，记录计数与字节哈希，其它缺失阻断、不重算法线。原骨（含手指）的名称、rest / 父级保持。
- **材质 Morph 直接迁移 `related_mesh_data` 至含原 Material 的分部 Mesh，保留 `material_data` 与数值 `material_id`。** “全部材质”目标使用无专属 Mesh 的 `None`；不删 Morph、不要求手工重绑。报告列出迁移。清理临时标记 / SDEF 运行时缓存后，写分离后严格基线与 `01`；随后着色及重复运行均使用该基线，不重新采样掩盖修改。
- 原生 `mmd_shader` 与 Morph 输入链保留。**Diffuse / Alpha 材质 Morph**通过桥接驱动游戏表面，Alpha 同时驱动同一原材质的描边；不是把初始 Alpha 再重复相乘。Ambient / Specular / Sphere 等完整视觉等价性未认证。
- 描边 shell 仅存在于**分部**的 Geometry Nodes 求值，不写回分部 Mesh、不插入替代材质槽；按分部局部面索引保留原材质各自宽度 / 色彩参数，以 FACE 属性区分 shell、屏蔽其 AOV 写入。shell 不写回不等于前面未拆网格；它也不是恒定像素宽度，开放边、叠层或接缝不会被自动焊好。
- 配置后，通过 MMD Tools 原生导入 VMD，选根物体、使用匹配的比例与 `PMX` 骨骼映射。正常 VMD / 形态键动作和实例 Diffuse / Alpha 变化不应被当成结构篡改；动画后可能需重新取景。
- 需要物理时，在高级设置点“**构建已导入的原生 MMD 物理（慢）**”。这是独立慢操作，一键渲染不反复 build / clean；没有已导入的刚体 / 关节就不会凭空生成。
- 物理前先保存最新 `02_...` 完整回退点，含配置后新增动作。已成功构建并验证时再次点为 no-op。失败必须打开最新回退文件，不凭 `is_built=True` 判断成功。
- **构建≠烘焙。** 从缓存起始帧连续播放；改动作 / 起始姿态 / 帧范围后自行清旧缓存并重新烘焙。插件不保证任意跳帧、任意舞蹈、无穿模或碰撞完全正确。

## 五、重复点击和出错时怎么退

- 同一配置重复运行会先严格校验，再渲染或 no-op，不叠加材质桥、描边、节点或物理。保存重开后仍须保留可验证的实际资源目录与文件，打包贴图不代表可以删掉原资源。
- 新 v3 守卫保护 ShapeKey 相对关系 / 分组 / use_relative / reference / frame / interpolation / lock_shape、全部稳定 typed attrs、全组和 UV 结构。允许正常 value / eval_time 动画、原生 slider / mute 与编辑选择，不从旧版本重采样基线。
- 当前渲染必需图须有效；隐藏 / 断开节点 / 嵌套组中的有效保留源图也会打包并复验 packed bytes 哈希。原本坏掉且未使用的旧 Toon 仅诊断，不变成必需输入；有效 retained 图打包失败仍阻断。
- 保存前只读拒绝重复非负 Material ID、无指针的旧数值 Morph 目标及指针 / ID 不一致，避免原生 save_pre 静默改目标。保存后若未知 handler 仍改动，旁写 `.INVALID_SAVE.json`、`trusted_checkpoint=False`；故障文件不算可信回退点，也不宣称已自动回滚。
- 配置后想换资源、JSON 关联或描边：先另存当前工程，再从 `00` 配置前回退点重做。当前新渲染策略是 `mmd-game.v2-native-cull-transparent-eye-shadow`；旧 0.2.1 缺此标识也不兼容，和 0.2.0 一样必须从原 PMX / `00` 重做，不重设旧守卫基线。
- **`00_配置前完整回退.blend`：** 原生分离 / ID 初始化 / 着色前的完整文件；恢复原网格布局或失败后重新配置用它。成功配置后面板默认指向 `00`。
- **`01_原生分材质_着色前回退.blend`：** provenance 与 Morph 迁移通过后、渲染场景 / 材质尚未挂接的已分离中间文件，路径在报告 `separated_checkpoint`；只能恢复该阶段，不会变回未分离网格，也不是允许从半完成状态重跑的入口。重做仍用 `00`。
- **`02_原生物理构建前回退.blend`（可能带序号）：** 独立构建物理前的最新完整文件，含配置后新增动作；物理失败用最近这份，面板在该操作时更新回退路径。
- “**打开完整文件回退点**”重新打开磁盘备份，**当前未保存改动会丢失**。原场景与渲染场景共享分部数据，**切回旧 Scene 不能撤销分离或材质挂接**；磁盘完整备份才是恢复依据。
- 原材质身份 / Morph 目标、网格 / 权重 / 法线、节点桥、GN / AOV 等不兼容修改会阻断重复运行，不会静默重建。物理半构建或配置未完成也不能继续叠加。
- 若提示“**配置已保存，渲染失败可再次点击**”，可先排查输出或渲染原因，再通过校验重试。若工程保存失败，不算配置成功；按诊断打开完整回退文件。

## 六、使用与验证边界

无角色门槛不等于会修复坏模型、错误 UV、缺原生节点、共用数据、穿模或 IK / 物理循环。不要用扫描成功替代视觉检查，也不要把短连续物理检查当作完整舞蹈或烘焙认证。

**本指南没有“所有测试已通过”的承诺。** 静态检查、mock 单测、真实配置 / 渲染、保存重开、Morph / VMD、连续物理与隔离 ZIP 安装各有独立范围；请以交付时的实际验证记录为准。

更多细节见[完整使用说明](<../zzz_mmd_toon/README.md>)。
