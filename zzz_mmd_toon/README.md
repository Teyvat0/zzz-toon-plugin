# 仿ZZZ渲染 · MMD 0.3.0（通用资源 · 原生分材质版）

使用流程是：**用户用 MMD Tools 自行导入绝区零 PMX → 选择对应角色的游戏材质 JSON 与贴图目录 → 扫描 → 一键配置并渲染**。无需运行外部 Python；插件会在建立渲染场景与着色前，调用 MMD Tools 原生“按材质分离”并验证数据来源，不要求用户提前手工拆分。分离会改变 Object / Mesh 数据块与局部材质槽 / 面索引，不能按旧版“不拆网格”理解。

**游戏 JSON 与贴图是必需输入。** 资源目录缺失或不是角色资源目录时会阻断。个别材质槽找不到足够证据时**不再阻断整体**：这些槽在映射列表顶部以红色标出，默认保留 MMD 原材质（不会伪装成游戏材质）；可手动为它们选 JSON，选择会保存到资源目录的 `zzz_mapping.json`，下次扫描自动沿用。点“一键配置并渲染”时若仍有未映射槽，第一次点击只提示，再点一次才忽略它们并渲染。

## 1. 环境与安装

- 目标环境是 **Goo Engine 4.4 + 已启用的 MMD Tools**；具体环境版本与验证范围以实际验证记录为准。普通 Blender 和其它版本没有等效降级保证；版本或 Goo 专用节点不兼容会中止。
- 在 Goo 中通过“编辑 → 偏好设置 → 插件 → 从磁盘安装”安装完整 ZIP，再启用“仿ZZZ渲染 · MMD”。
- **无需另选模板。** 渲染场景（相机、Sun、三个头部坐标控制对象、World、ViewLayer / Eye 双层 AOV、合成器）、Toon 着色器、描边和灯光节点组全部由插件代码生成，包内不含 .blend 资产。
- 安装包**不包含角色 PMX、游戏贴图、游戏 JSON 或 MMD Tools**；也不自动安装其它插件。贴图打包到用户生成工程不等于取得再分发许可。

## 2. 第一次配置

1. 先保留原工程副本，再用 MMD Tools **自行导入 PMX**。常用基线为默认单位场景、导入比例 `0.08`、保留原日文骨名，并导入 Mesh、Armature、Morphs、Display；要用物理时还须导入 Physics。比例和骨数不是角色准入白名单，但任意改造模型并不因此获得兼容保证。
2. 建议在干净导入副本上先配置渲染，再导入 VMD、编辑 Pose、构建物理或加入复杂自定义动画。不要预先用其它渲染器替换 MMD Tools 原生材质节点；插件依赖其原生 Diffuse / Alpha 输入。配置前退出原生材质 Morph 临时预览、UV Morph 编辑预览；旧式 UV Morph `DATA` 索引、Mesh-only drivers、以原网格为目标的外部约束 / 修改器需先在独立文件处理与验证，具体阻断见第 4 节。
3. 切到**对象模式**，选中 MMD 根物体；也可选中所属骨架或网格。按 `N` 打开“仿ZZZ渲染”侧栏。插件不负责导入 PMX。
4. 在“**必需：对应角色JSON与贴图目录**”选择这一角色、这一套外观的完整资源根目录，通常包含 `Materials` 与 `Textures` 两个子目录；也可以选择其中的 `Materials`，插件会使用其父目录。不要选 PMX 自带的 `tex` 文件夹，也不要把多个角色或多个无法区分的外观资源混在一个目录中。
5. 选择角色资源文件夹（含 Materials / Textures），点击“**扫描材质 / 自动映射**”。扫描后，材质列表出现在面板里：红色置顶的是未映射的槽，其余是已自动关联的槽。点选一个槽可改选候选 JSON、改为保留 MMD 原材质、调该槽描边宽度。资源目录错误会直接报错。
6. 自动关联的 JSON 身份、语义域和 Alpha 由算法给出；你只能在该槽自己的候选 JSON 里改选（不能任意指定角色），选择会如实标记为用户决定。“高级与回退”子面板可调全局描边倍率，并提供“仅配置，不渲染”和文件回退点。选中某个槽后，可在“材质映射”里设置它的描边、背面剔除和**透明材质**（自动 / 透明 / 不透明）：镜片、玻璃、薄纱这类槽按“材质 Alpha × 贴图 Alpha”半透明显示，且不生成描边；自动判断依据是材质名或 PMX Alpha，你的选择会写入映射文件并在下次扫描时沿用。第一次配置前调整描边；配置后若改变描边或映射，需从文件回退点重做。
7. 点击“**一键配置并渲染**”。资源与输入预检后，依次写 `00` 完整回退点 → 原生分材质（`clean_shape_keys=False`）→ exact provenance 等价核对与材质 Morph 引用迁移 → 写 `01` 分离后、着色前回退点 → 建立渲染场景 → 挂接游戏材质与逐面描边、灯光 / 头部坐标 / 双层合成。校验后打包实际使用的有效贴图并保存新工程，再渲染。环境可先预检，但渲染场景实际创建在原生分离清理完成之后。也可在“高级与回退”子面板中先用“仅配置，不渲染”。
8. 在唯一的时间戳输出目录中查看新工程、PNG、配置验证报告和回退文件。输出路径也显示在面板状态中；插件拒绝覆盖已有工程和回退点，不修改原始 PMX 或资源文件。

输出位置不再需要设置：已保存工程使用其所在目录下的「仿ZZZ渲染输出」文件夹，未保存工程使用临时目录。为长期保留结果，请先保存工程。

## 3. “通用”指同一套算法，不是任意输入百分百成功

运行时没有角色名单、专用 profile、模型路径或骨 / 材质数量准入条件。不同绝区零角色走同一条流程：

1. 扫描所选目录，保留每个 JSON 的独立身份、参数、纹理引用和状态，不按 MainTex 去重。
2. 优先解析可验证的显式纹理名称；PMX 原主贴图与游戏主贴图通过像素相似度关联 **atlas**。图像相似只说明贴图族关系，不直接证明材质身份。
3. 再对每个原材质分别依据中 / 日 / 英语义、透明度、双面与 JSON 状态判断域和候选。脸、眼、眉即使共用一张 atlas，也保持各自的原材质身份与语义；同图的透明变体也不合并。HairShadow 效果通道不会被当成头发表面替代品。
4. 无 `Name` 的非空纹理引用，只在结构关系唯一，或有独立 PMX 像素 atlas 证据时推断同族贴图，记录为 `inferred` 并保留证据。**这是结构 / 图像推断，不是 Unity PathID 解码，也不是游戏原绑定的确证。** 原始 Name / FileID / PathID 留作诊断，不跨 JSON 把指针数字当作同一纹理。
5. 多候选、零误差并列或状态证据不足时，该槽标为未映射（保留 MMD 原材质），不靠文件排序选第一项；基础 JSON 与其 `_T` 变体共用同一套贴图时，按基础 JSON 处理。无可靠绑定的可选 MatCap 不猜槽位，记录未解析并关闭相应贡献；这会损失效果，不等于资源已经完整还原。
6. 少量编辑过的翅膀 / 叠层，只有满足唯一语义或严格几何重合证据时才借用数据参数，并标记推断、保留原色和 Alpha；这不是所有改图、叠层或特殊效果都受支持的承诺。
7. **参数关联与自动关闭是两份独立证明。** 同源叠层只在**100% exact 有向三角位置、全部 UV 与重复计数**被已关联表面覆盖，且独立语义、所有排名前兼容 JSON 的完整路径 / 数据绑定族唯一时，才可借用 JSON 参数；始终保留源色、Alpha 与可见性。这不证明权重、形态键或动画重复。`MME_DUPLICATE_OFF` 还须完整坐标 / 权重 / 全部 ShapeKey 与元数据 / 作者法线空间证明、无未覆盖三角、唯一族、无相关 Morph / 动画风险、供体与效果层双面状态一致、可解码 sphere **ADD（`sphere_texture_type == '2'`）**；主图 / sphere 只接受无 Image 动画的静态 `FILE` / `GENERATED`，且源主图**全部像素 Alpha max `<= 0.35`**。不以序列 / 影片当前帧证明整个时间范围。独立 smooth 法线 fan 不能证明、权重不同或其它证据不足时 **保留显示，不自动关闭**；关联本身也不唯一则阻断。已停用旧的 `> 0.995`、round-6 无向位置集合判据，不能用它冒充安全隐藏证明。
8. **背面剔除按数据来源，而非角色名决定。** 保留原 Material 已开启的剔除，以及 PMX `is_double_sided=False` 的单面要求；直接 JSON / 独立语义表面使用 Goo 预览状态（明确 `_Cull=2` 不被 `_DoubleSided=1` 抵消；眼、口和贴花域保持其双面策略）；仅借参数的独立叠层不继承供体剔除，保留自己的原生状态。它修复单面外套内衬 / 重叠头发表面的错误颜色，不改颜色或法线；不是所有 Unity pass / 游戏剔除规则的逐项翻译。自动关闭还要求供体与效果层**最终剔除覆盖一致**，不能只比较原生双面位。
9. **目影用有色 Transparent BSDF，不再执行黑色 Forward。** 无贴图目影保持常量覆盖；贴图目影仍使用独立解析的原 atlas Alpha。透射 RGB 与原生实例 Alpha（及贴图 Alpha）混合，Alpha Morph 为 0 时成为白色透射；不删网格、不混并眼球 / 眉毛 / 目影身份。配置后在目影映射行可调“目影透射颜色”：越接近白越淡，颜色输入的 A 不作为不透明度；唯一该 RGB(A) 控件是允许的动态输入，链接 / 节点 / 其它状态仍受守卫。默认值是线性透射 `(.713,.687,.687)`，不是游戏参数原样复现。目影不生成描边、不写 Forward AOV。
10. 命中该策略的分部仍保留网格、原 Material 与 Morph，归入 `ZZZ_MME重复叠层_保留关闭_...`，对象名以 `MME_OFF_` 开头；仅默认设 `hide_render=True`，**不删除、不硬改发色、不改写源图或输入文件**。可在该分部的 Outliner 渲染可见性（相机开关）手动恢复；原 `hide_render` 值记录在对象属性 `zzz_effect_was_hide_render`，判据记录在报告与 `zzz_effect_parts`。取消隐藏恢复的是**当前游戏 Forward 叠层显示，不是原 MME 原样效果**。要恢复未挂游戏桥的原生材质状态，使用 `00`（原网格布局）或 `01`（已分离、未着色）完整文件，而不是只切回旧 Scene。

**两类问题要区分：**

- **资源不足 / 关联不唯一：** 先补齐对应外观的 JSON、必需主贴图与数据图，排除同名文件、重复 JSON stem、错误目录或不匹配的 PMX 贴图。修复后重新扫描；不会走无资源回退。
- **着色能力边界：** 即使资源齐全且关联成功，未实现的特效、游戏渲染状态或不匹配的 UV 也可能无法复现；不能靠“映射完成”证明画面等同游戏。

## 4. 原生分材质、数据证明与 Morph 迁移

- **0.2.1 会实际拆分网格。** 使用与 MMD Tools 界面相同的 `bpy.ops.mmd_tools.separate_by_materials(clean_shape_keys=False)`，在渲染场景 / 着色前完成。分部 Object / Mesh 身份、名称、局部顶点编号、材质槽和面材质索引可变；不承诺原 Object / Mesh ID 或原槽布局不变。保留的是各原面所引用的原 **Material 数据块与 Material ID**，不按共享 MainTex 合并、不换新渲染 Material 来重定向 Morph，也不重绑 / 自动生成权重。
- **先证明来源，再建立新严格基线。** 分离前为每个源网格记录临时 POINT / EDGE / CORNER / FACE 原索引；分离后以 exact provenance 核对坐标、全部命名权重（含显式零权重、未使用组与组锁）、全部形态键坐标及元数据、所有 UV 层与 active / render / clone / 默认颜色层结构、边 / 角 / 面绕序、逐面原 Material 身份、平滑标记与全部稳定作者属性 typed bytes。原面和原角必须各覆盖一次；材质边界允许复制顶点 / 边。不会用四舍五入后的几何或运行时 `corner_normals` 缓存代替证明，也不按 dot / ZZZ 前缀或描边同名组漏掉作者数据。
- 已导入的作者法线保护的是 **`custom_normal` signed-short2 原始存储、`sharp_edge` / `sharp_face` 与完整边 / 角拓扑、平滑标记**，不是不稳定的解码法线缓存。若原生分离省略全 False 的 sharp / 现有 UV pin 属性层，仅在原层存在、来源子集逐值全 False 时按原索引恢复该层，并记录计数与字节哈希；非 False 丢失或其它自定义层丢失仍阻断，不重算法线。父级 / 变换 / 修改器 / 动画与 driver 自引用须通过等价核对；原骨（含手指骨）的名称、rest / 父级保持。所有原始骨可显示、可选；MMD 内部 shadow / dummy 辅助骨组仍可能隐藏，不等于丢失原骨。
- **直接迁移材质 Morph 的 `related_mesh_data`。** 原 `material_data` 和数值 `material_id` 保持，旧网格引用改指含该原 Material 的分部 Mesh；同一 Material 可对应多个分部，现代 `material_data` 仍为权威目标。“全部材质”目标无专属 Mesh，使用 `None`。迁移记录写入 `prepare.material_morph_migrations`，不以删除 / 重建 Morph 或手工重绑代替迁移。未初始化的负值 Material ID 只在 `00` 完整回退后由 MMD Tools 自身 API 初始化并记录；文件内重复非负 ID 会阻断。
- provenance、Morph 迁移与原骨核对完成后清理临时来源标记、清除原生 SDEF 运行时缓存，取得**分离后严格作者数据基线**并写 `01` 回退点；场景 / 材质挂接必须仍匹配该基线。后续 no-op 使用这份已验证基线，不重新采样来掩盖外部改动。
- **原生分离的输入边界不是角色白名单。** 当前会阻断旧式 UV Morph `data_type == 'DATA'`、含 `_temp` 的材质临时预览、`__uv.` UV 编辑预览、仅 Mesh drivers 而无 Action / NLA 的组合，以及以原网格为目标的外部对象约束 / 修改器；还会拒绝空网格、重复 Material ID、外部共用 Mesh / Material 或只读库等。复杂自定义动画、外部引用未被全面认证，建议先在独立副本清理并验证；具体以当前 `native_split` 与预检诊断为准，不要绕过失败项。
- 原生 `mmd_shader` 节点和 Morph 输入链保留，以私有桥接组暴露实例 **Diffuse / Alpha**，使正常材质 Morph 继续驱动游戏表面。Alpha 同时控制该原材质对应的描边，不在映射表重复乘入一份初始透明度。
- 描边由 Geometry Nodes 在**分部求值**时按其局部面材质索引生成 shell；原面与 shell 用 FACE 域属性区分，使用同一原 Material，shell 不写回分部 Mesh，也不插入替代材质槽。原材质仍各有宽度 / 色彩参数，shell 的 AOV 写入受屏蔽。这里的“shell 不写回”不等于前面的原生分离没有发生。
- 这不是对全部材质 Morph 参数或全部 MME 效果的等效承诺：**Ambient / Specular / Sphere 等与游戏着色的完整等价性未认证**。已有 Morph 目标仍在，不等于每种参数都有相同视觉效果。

## 5. VMD、原生物理与连续播放

- 推荐**先配置渲染，再导入动作**。在对象模式选根物体，通过 MMD Tools 原生导入 VMD，使用与模型匹配的比例和 `PMX` 骨骼映射；一般不要勾选“当前姿态作为静置姿态”。分材质后各分部保留完整形态键与原骨权重、经迁移的材质 Morph 目标，继续使用原生动作入口；这不认证任意已有自定义动画组合。
- 物理请用 MMD Tools 自带的物理面板（Build / Clean）；本插件不再提供物理按钮，一键渲染也不会构建或清理物理，PMX 未导入刚体或关节时不会凭空补造。
- 物理操作前自动另存最新 `02_...` **完整文件回退点**，包含配置后新增的 VMD / Action 等当前工程数据。构建完成并校验后保存物理工程；已构建状态只在验证有效后返回 no-op，不叠加构建。
- 物理构建若失败，应打开最新 `02_...` 回退点；不能只看到 `is_built=True` 就认为成功，也不要在半构建状态反复点按钮。
- **构建不等于缓存烘焙。** 从缓存起始帧连续播放；更改动作、起始姿态、刚体参数或帧范围后，自行清理旧缓存并重新烘焙。插件不清理用户缓存，不保证任意跳帧一致、任意舞蹈无穿模或碰撞完全正确。

## 6. 重复点击、保存与完整文件回退

- 同一配置再次运行先做严格守卫验证，再渲染或返回 `already_configured_noop`；不叠加材质桥、节点组、逐面描边或物理。资源目录、实际使用资源哈希、原材质身份 / Morph 目标、网格、骨架与关键渲染依赖须保持兼容。
- 新作者结构 schema 为 `authored-mesh.v3-shape-attribute-uv-structure`：保护全部稳定属性的名称 / 类型 / 域 / 计数 / typed bytes、全部组 / 权重、UV 结构，以及 ShapeKey `relative_key`、`vertex_group`、`use_relative`、reference、frame、interpolation、lock_shape 与坐标。正常 `value` / `eval_time` 动画、原生 VMD 所需 slider 范围 / mute 和编辑选择不冻结；旧 schema 不自动升级或重采样。
- 打包分成两路：当前可见渲染依赖必须有效；同时遍历所有保留分部（含隐藏、断开节点和嵌套组）的有效源图像，打包并记录实际 packed bytes 哈希，重开 / 重复运行继续验证。断开且原本无效的旧 Toon / Sphere 图像只报诊断，不升级成必需输入；有效保留图打包失败则阻断。打包不代替原资源目录 / 哈希检查。
- 每次保存前先做**只读**原生 ID / 材质 Morph 检查：全文件重复非负 Material ID、无指针的旧数值目标、指针 / ID 不一致会在 `00` 前阻断，避免 MMD Tools `save_pre` 静默重编号或清空目标。保存后再次比对；未知第三方 handler 若仍改动目标，保存不算可信回退点，旁写 `.INVALID_SAVE.json`（`trusted_checkpoint=False`），保留故障文件供诊断，不宣称自动回滚。
- 新渲染策略标识为 `mmd-game.v2-native-cull-transparent-eye-shadow`；缺该标识的旧 0.2.1 工程也必须从原 PMX / `00` 重做，绝不重设其 shader 基线来迁就新规则。
- 正常的 VMD、形态键动作、实例 Diffuse / Alpha 及唯一目影透射颜色控件变化不是结构篡改；可调整相机 / 灯光。替换原材质 / 桥组、修改原网格 / 权重 / 法线、改受守卫的节点 / 修改器 / AOV 等，不会被静默重建掩盖；具体以校验诊断为准。
- 已配置后改资源、映射或描边，不是热重建：先另存当前工程，再打开 `00` 配置前回退点重新配置。旧版配置（含 0.2.0）不能直接叠加 0.2.1，应从原工程 / 原 PMX 或配置前回退点开始，不能重设旧基线来绕过版本检查。
- **`00_配置前完整回退.blend`：** 分离 / ID 初始化 / 着色前的完整文件，是恢复原网格布局、失败后重新配置的权威起点；成功配置后面板默认指向它。
- **`01_原生分材质_着色前回退.blend`：** exact provenance 与 Morph 迁移通过后的已分离中间文件，渲染场景 / 材质尚未挂接；供检查或手动恢复到该阶段，不会还原为未分离状态，也不是允许从半完成 phase 再点一键配置的入口。文件位置记录在配置报告 `separated_checkpoint`；需要重做请打开 `00`。
- **`02_原生物理构建前回退.blend`（可能带序号）：** 每次独立物理构建前的最新完整文件，包含配置后新增动作等；物理失败应使用最近这份，而不是较早 `00` / `01`。物理操作会更新面板回退路径。
- “**打开完整文件回退点**”重新打开所选磁盘备份，**放弃当前未保存改动**，不是对象级撤销。原场景与新渲染场景共享分部模型数据，切回旧 Scene **不能撤销**原生分离或材质挂接；完整文件回退点才是权威恢复依据。
- 工程保存失败不会被报告成配置成功。若配置工程已保存、只有渲染失败，面板会说明“配置已保存，渲染失败可再次点击”；解决输出 / 渲染问题后，可在通过守卫验证的前提下重试。

## 7. 视觉、兼容性与验证边界

- 这是使用 Goo 着色器重建的**仿 ZZZ 预览**，不是游戏原着色器逐像素复现。Face SDF、N / M / A 数据解码、可解析 MatCap、独立逐面描边以及 Eye / Hair AOV 合成均依赖对应资源与 UV。
- Eye_E / `_EyeColorMap`、物理透射、部分发光 / 变身 / 武器效果与其它未连接纹理特性未实现或仅近似。Unity blend / depth / stencil 状态会保留为元数据，但不完整等价；最终原材质使用保留原生 Alpha 的 HASHED 桥接策略，不是原游戏状态的逐项直译。
- Face lightmap 依赖匹配的脸 UV 与头部坐标。头骨无法识别时只有渲染坐标回退，不会生成变形骨或重新赋权，也不保证动画中与正确头骨跟随相同。
- 描边是带相机距离上限的空间宽度，**不是恒定像素宽度**；边界不焊接，开放面、重复叠层与接缝可能显露。自动相机只适配配置时求值姿态，动作后可能需要重新取景。
- 无角色白名单不意味着任意损坏、任意改造或多模型共用数据都可直接配置。缺原生材质节点、空槽、外部共享 Mesh / Material、只读链接库或缺关键依赖时会拒绝；原模型的穿模、IK / 依赖循环与异常物理不会因此自动修好。
- **本说明不宣称所有测试通过。** 静态检查、mock 单测、真实配置 / 渲染、保存重开、Morph / VMD、连续物理及隔离 ZIP 安装是不同证据；部分检查通过不能替代其它项，最终以随交付提供的实际验证记录及其范围为准。

## 8. 使用权与分发

遵守模型、游戏资源与 MMD Tools 各自的使用条件。插件不授予角色资产再分发权，也不要将自动打包贴图的新工程当作可任意分发的模型包。
